[**breaking**] The `protocol` and `device_authorization_grant` fields of
`QrAuthMessage::LoginProtocol` have been merged into a single `protocol` field of
the new `LoginProtocolData` enum, which carries the data specific to the picked
protocol, or an `UnknownLoginProtocol` for protocols we don't support.
Previously an `m.login.protocol` message without a `device_authorization_grant`
field failed to deserialize, so a device that picked a different protocol got a
decoding error instead of an `m.login.failure` with the `unsupported_protocol`
reason.
